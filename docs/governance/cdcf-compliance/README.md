## How to Use This Folder

**If you are a CDCF reviewer:** Read this README for the status overview, then read each criterion document in sequence. C2 and C5 contain the most substantive governance commitments. C4 names the two open gates that block final publication claims.

**If you are a diocese or institution evaluating adoption:** Start with [c2-human-accountability.md](c2-human-accountability.md) for the decision authority framework, then [c6-deployment-governance.md](c6-deployment-governance.md) for the governance specification that governs how CDFI scores translate into institutional deployment decisions.

**If you are adapting this framework for another tradition:** The subgroup protocol in [c5-subgroup-protocol.md](c5-subgroup-protocol.md) is tradition-agnostic and transferable. The responsibility boundary in [c3-c7-responsibility-boundary.md](c3-c7-responsibility-boundary.md) applies regardless of tradition.

## What the CDFI Framework Is and Is Not

| The CDFI Framework IS | The CDFI Framework IS NOT |
|----------------------|--------------------------|
| A scoring methodology for evaluating AI models against doctrinal standards | A deployment decision-maker — no score deploys or prohibits a model automatically |
| A publication of evaluation governance infrastructure with a citable DOI | An endorsement of any AI model or product |
| A methodology any institution can adapt for its own tradition | A substitute for human theological judgment |
| Grounded in seven published AI safety research publications | Training data for any AI model |
| An instrument for measuring doctrinal reliability at inference time | A mechanism for evaluating whether an AI project should enter CDCF incubation |

The CDCF Project Vetting Criteria asks: *should this project enter the Foundation?* The CDFI asks: *how doctrinally reliable is this AI model?* These are different instruments solving adjacent problems. The documents in this folder connect them.
